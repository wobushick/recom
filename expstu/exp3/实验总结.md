### ✓ 实验2：深入理解RDD操作算子的分类与区别

**目标**: 通过编程实践，深刻区分Transformation（转换）算子与Action（行动）算子的执行时机

**关键发现**:
- Transformation算子（map、filter等）**不会立即执行**，具有**惰性求值**特性
- Action算子（collect、count等）**立即触发作业执行**
- 每次Action都会触发RDD的重新计算（除非使用了缓存）

**观察数据**:
```
第1次count(): 3 (用时: 0.2625s)
第2次count(): 3 (用时: 0.4284s)
结论：都重新计算了一遍
```

**关键代码示例**:
```python
mapped_rdd = rdd_base.map(lambda x: x * 2)        # Transformation - 不执行
filtered_rdd = mapped_rdd.filter(lambda x: x > 5) # Transformation - 不执行
result = filtered_rdd.collect()                     # Action - 立即执行所有Transformation
```

### ✓ 实验8：掌握高级聚合算子combineByKey的原理与应用

**目标**: 深入剖析combineByKey的底层运行流程，能够利用该算子解决复杂聚合统计问题

**应用场景**: 计算每个部门的员工统计信息

**部门统计结果**:
```
部门      员工数    工资总和    平均工资    最高工资    最低工资
D001      9        62200       6911        8500        5500
D002      8        75800       9475        10400       8800
D003      8        98300       12288       14200       10500
D004      6        45500       7583        8200        6800
D005      4        64500       16125       17200       15000
```

**combineByKey三个核心函数**:
```python
def create_combiner(salary):
    """第一次遇到某个Key时的初始化"""
    return (1, salary, salary, salary)  # (count, sum, max, min)

def merge_value(acc, salary):
    """在同一分区内合并值"""
    return (acc[0] + 1, acc[1] + salary, max(acc[2], salary), min(acc[3], salary))

def merge_combiners(acc1, acc2):
    """合并不同分区的累计器"""
    return (acc1[0] + acc2[0], acc1[1] + acc2[1], max(acc1[2], acc2[2]), min(acc1[3], acc2[3]))

# 使用combineByKey
dept_stats = dept_salary.combineByKey(create_combiner, merge_value, merge_combiners)
```

**效率优势**:
- combineByKey相比groupByKey的优势：在Map阶段就进行了局部聚合，减少网络传输
- 适用于复杂聚合场景，比简单的map+reduce更高效

def parse_doc(line):
    """将文档解析成(word, doc_id)对"""
    parts = line.split(",", 1)
    if len(parts) > 1:
        doc_id = parts[0]
        content = parts[1]
        return [(word.lower(), doc_id) for word in content.split()]
    return []

# 构建倒排索引

## 关键知识点总结

### 1. RDD的特点
- **Immutable**: 一旦创建就不能改变
- **Lazy Evaluation**: 转换算子不会立即执行
- **Distributed**: 数据分布在集群的多个节点上
- **Fault-Tolerant**: 基于血缘关系的容错机制

### 2. Transformation vs Action
| 特性 | Transformation | Action |
|------|--------|--------|
| 执行时机 | 惰性，不立即执行 | 立即执行 |
| 返回值 | 新的RDD | 结果或副作用 |
| 示例 | map, filter, flatMap | collect, count, take |

### 3. 分区的重要性
- 分区数决定了并行度
- 合理的分区设置能大幅提升性能
- repartition和coalesce用于调整分区数

### 4. 缓存策略
- cache()使用内存缓存
- persist()可以指定多种存储级别
- 对于多次使用的RDD必须缓存

### 5. 常用业务场景
- **数据清洗**: filter + map
- **数据统计**: reduceByKey + combineByKey
- **数据排序**: sortByKey + sortBy
- **关键词检索**: flatMap + groupByKey（倒排索引）

## 实验心得

1. **理解惰性求值**: Spark的核心优化策略，通过延迟执行来构建最优的执行计划
2. **分区机制很重要**: 合理的分区设置能显著提升并行计算的效率
3. **算子选择很关键**: groupByKey vs reduceByKey vs combineByKey各有使用场景
4. **缓存要谨慎**: 虽然缓存能加速计算，但要权衡内存消耗
5. **组合使用算子**: 实际工作中往往需要多个算子组合使用
