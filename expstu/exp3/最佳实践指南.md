# 实验三 - 最佳实践与常见错误

## 常见错误与解决方案

### 1. ❌ 错误：在Driver端使用collect()处理大数据集

```python
# 错误做法
large_rdd = sc.textFile("huge_file.txt")
all_data = large_rdd.collect()  # OOM风险！

# 正确做法
result = large_rdd.take(1000)   # 只获取前1000条
# 或者
count = large_rdd.count()       # 只统计数量
```

**原因**: collect()会将所有数据从Worker节点传输到Driver节点，容易导致内存溢出

---

### 2. ❌ 错误：多次使用同一RDD但没有缓存

```python
# 错误做法
rdd = sc.textFile("data.txt")
count1 = rdd.count()      # 执行一次
count2 = rdd.count()      # 再执行一次
sum_val = rdd.sum()       # 再执行一次

# 正确做法
rdd = sc.textFile("data.txt").cache()
count1 = rdd.count()      # 执行一次并缓存
count2 = rdd.count()      # 从缓存读取
sum_val = rdd.sum()       # 从缓存读取
```

**原因**: 没有缓存会导致RDD被重复计算，浪费资源

---

### 3. ❌ 错误：分区数设置不当

```python
# 错误做法1: 分区数太少
rdd = sc.textFile("data.txt", minPartitions=1)  # 无法并行

# 错误做法2: 分区数过多
rdd = sc.textFile("data.txt", minPartitions=10000)  # 任务过多，开销大

# 正确做法
# 通常设置为 CPU核数 * 2 到 CPU核数 * 3
rdd = sc.textFile("data.txt", minPartitions=8)
```

**原因**: 分区数影响并行度和任务调度开销

---

### 4. ❌ 错误：在transformation中进行序列化问题

```python
# 错误做法：在lambda中使用非可序列化对象
class MyClass:
    def __init__(self):
        self.connection = open("file.txt")  # 不可序列化

def apply_func(x):
    return x * 2

rdd.map(lambda x: apply_func(x))  # 虽然函数看起来简单，但可能有隐藏的序列化问题

# 正确做法
def process(x):
    return x * 2

rdd.map(process)  # 使用顶层函数
```

**原因**: 闭包中的变量必须可序列化才能在Worker节点上执行

---

### 5. ❌ 错误：数据倾斜导致某个任务特别慢

```python
# 错误做法：没有处理键值不均匀分布
rdd = sc.textFile("data.txt")
result = rdd.map(lambda line: (line.split(",")[0], line)) \
            .groupByKey()  # 如果某个key特别多，会导致该分区特别大

# 正确做法：使用二级排序或其他技巧
# 方法1：使用更多的分区
result = rdd.map(lambda line: (line.split(",")[0], line)) \
            .repartition(100) \
            .groupByKey()

# 方法2：添加随机前缀（对于combineByKey尤其有效）
rdd_with_prefix = rdd.map(lambda line: (
    (line.split(",")[0], random.randint(0, 10)), line
)).reduceByKey(lambda a, b: a + b)
```

**原因**: 数据倾斜会导致某些任务成为瓶颈

## 性能优化技巧

### 1. 合理使用持久化级别

```python
# 根据数据量选择合适的持久化级别

# 小数据集（< 1GB）：使用内存
rdd.persist(StorageLevel.MEMORY_ONLY)

# 中等数据集（1-10GB）：使用内存+磁盘
rdd.persist(StorageLevel.MEMORY_AND_DISK)

# 大数据集（> 10GB）：序列化后存储
rdd.persist(StorageLevel.MEMORY_ONLY_SER)

# 只需要一次性计算：不需要缓存
rdd.count()
```

---

### 2. 优先使用reduceByKey而不是groupByKey

```python
# 较慢的做法
result = rdd.groupByKey().mapValues(lambda vals: sum(vals))

# 更快的做法
result = rdd.reduceByKey(lambda a, b: a + b)

# 最快的做法（如果需要多种聚合）
result = rdd.combineByKey(
    lambda v: (v, 1),                           # create
    lambda acc, v: (acc[0] + v, acc[1] + 1),   # merge value
    lambda acc1, acc2: (acc1[0] + acc2[0], acc1[1] + acc2[1])  # merge combiner
)
```

**原因**: reduceByKey在Map阶段就进行了局部聚合，减少网络传输

---

### 3. 提前过滤数据

```python
# 较慢的做法：处理所有数据再过滤
result = rdd.flatMap(process).map(transform).filter(condition)

# 更快的做法：尽早过滤
result = rdd.filter(condition).flatMap(process).map(transform)

# 最优做法：在读取时就过滤
result = sc.textFile("data.txt") \
    .filter(lambda line: "error" in line) \  # 尽早过滤
    .map(parse_line) \
    .filter(some_condition)
```

**原因**: 减少传输和转换的数据量

---

### 4. 使用广播变量共享只读数据

```python
# 较慢的做法：每个任务都读一遍参考数据
reference_data = read_reference_data()  # 10MB

result = rdd.map(lambda x: lookup_in_reference(x, reference_data))

# 更快的做法：使用广播变量
broadcast_ref = sc.broadcast(reference_data)

result = rdd.map(lambda x: lookup_in_reference(x, broadcast_ref.value))
```

**原因**: 广播变量只需传输一次，不是每个任务都传

## 代码规范

### 1. 使用顶层函数而不是匿名函数（当函数复杂时）

```python
# ❌ 不推荐（复杂逻辑）
result = rdd.map(lambda x: {
    "id": x.split(",")[0],
    "name": x.split(",")[1],
    "value": int(x.split(",")[2]) * 100
})

# ✓ 推荐
def parse_line(line):
    parts = line.split(",")
    return {
        "id": parts[0],
        "name": parts[1],
        "value": int(parts[2]) * 100
    }

result = rdd.map(parse_line)
```

### 2. 添加注释和日志

```python
# ❌ 不推荐
rdd1 = rdd.filter(lambda x: x > 100)
rdd2 = rdd1.map(lambda x: (x, x*2))
result = rdd2.collect()

# ✓ 推荐
# 过滤出大于100的值
rdd1 = rdd.filter(lambda x: x > 100)
print(f"Filtered RDD count: {rdd1.count()}")

# 计算值和其平方
rdd2 = rdd1.map(lambda x: (x, x*2))

# 收集结果进行最终处理
result = rdd2.collect()
```

### 3. 错误处理

```python
# 处理可能的解析错误
def safe_parse(line):
    try:
        parts = line.split(",")
        return (parts[0], int(parts[1]))
    except (IndexError, ValueError):
        return None

# 过滤掉解析失败的行
result = rdd.map(safe_parse) \
            .filter(lambda x: x is not None) \
            .count()
```

## 常见问题Q&A

**Q1: 什么时候应该使用reduceByKey而不是groupByKey?**

A: reduceByKey有局部聚合的优势，所以大多数情况下都应该使用reduceByKey。只有当你需要原始的值列表时才用groupByKey。

---

**Q2: 如何处理非常大的RDD（> 100GB）?**

A: 
1. 增加分区数（通常为CPU核数的3-4倍）
2. 使用mapPartitions而不是map（效率更高）
3. 使用广播变量共享小的参考数据
4. 考虑使用数据湖（Parquet格式）而不是纯文本
5. 启用动态分配（dynamic allocation）

---

**Q3: RDD和DataFrame有什么区别?**

A: 
- RDD：底层API，类型安全，支持Python object
- DataFrame：高层API，经过优化，支持SQL查询
- 对于结构化数据，优先使用DataFrame

---

**Q4: 如何在Spark中使用Python第三方库?**

A:
```python
# 方法1：使用spark-submit时指定
# spark-submit --py-files lib1.py,lib2.py script.py

# 方法2：在代码中导入
import sys
sys.path.insert(0, "path/to/lib")

# 方法3：使用PySpark的资源管理
conf = SparkConf()
conf.set("spark.python.worker.reuse", "False")
```
